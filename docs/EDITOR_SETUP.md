# עבודה מ־Codex, VS Code ואנטיגרביטי

אותו מאגר Git ואותם מסמכי Markdown ישמשו בכל סביבת פיתוח. התמיכה האוטומטית ב־AGENTS, סקילים, MCP וסאב־אייג׳נטים תלויה בלקוח ובגרסתו; אין להניח שכל עורך קורא את כל הקבצים אוטומטית.

## הוראות אחידות

1. Clone למחשב או פתח עותק קיים של המאגר.
2. פתח את תיקיית השורש בעורך שבחרת.
3. הנחה מפורשות את העוזר לקרוא `AGENTS.md`, `HANDOFF.md`, `docs/BUILD_PLAN.md` ואת `prompts/BUILD_PROJECT.md`.
4. בקש ביצוע B00 והמשך המשימה הראשונה הפתוחה. אם סאב־אייג׳נטים/סקילים לא זמינים, בצע תפקידים ברצף ותעד את פער דרישת התרגיל.
5. בסיום סשן: בדיקות, HANDOFF ו־commit; push לענף העבודה במאגר שהמשתמש הגדיר.

## Codex

תצורות האייג׳נטים ההתחלתיות ב־`.codex/agents/`; בדוק שהגרסה המותקנת טוענת אותן. `.codex/config.example.toml` אינו פעיל אוטומטית. אין לדרוס תצורה אישית קיימת. חיבורי MCP של ChatGPT אינם עוברים בהכרח ל־Codex המקומי.

## VS Code

אפשר להשתמש בהרחבת Codex אם קיימת גישה, או בעוזר אחר. העבודה בקבצים אינה מחייבת הרחבה מסוימת. פתח את `moh-ai-community.code-workspace` אם נוח; אין התקנות extensions או חשבונות אוטומטיות.

## אנטיגרביטי

אפשר לפתוח את אותו clone ולהדביק את אותה הודעת בנייה. לא אומתו בחבילה תחביר תצורה ייעודי, עלות או יכולות אייג׳נטים של אנטיגרביטי. אל תעתיק תצורת Codex כתחליף לתצורת לקוח אחרת; השתמש בהנחיות Markdown ובדוק אינטגרציות בתיעוד הרשמי של העורך בפועל.

## עבודה בשני עורכים/מחשבים

אל תערוך את אותם קבצים בו־זמנית דרך שני עוזרים. לפני תחילת עבודה: pull כשאין שינויים לא שמורים, קרא HANDOFF ובדוק branch. בסיום: commit ו־push, ואז העורך הבא מושך וקורא את נקודת ההמשך. אין force push אוטומטי או דריסת שינויים מקומיים כדי לפתור קונפליקט.
