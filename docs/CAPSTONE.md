## תיק הגשה מומלץ

`submission/README.md`: מה הבעיה, למי, מה בנינו, איך מריצים ומה מגבלותיו.

`submission/research.md`: מקורות, טענות, נגישות, תאריך ואימות.

`submission/process.md`: workflow, prompt וסקיל בפועל; agents שהופעלו באמת לעומת תפקידים לוגיים.

`submission/integrations.md`: MCP חיצוני פעיל, קריאה ותוצאה לא רגישה, סקיל שהופעל והיכן תרם.

`submission/review.md`: v1 → ביקורת → שינוי → v2. להשאיר את הטיוטות נגישות ולא לכתוב רק ״שופר״.

`submission/output/`: לפחות פוסט עם PNG; יעד נוסף MP4+SRT, בהתאם לדרישת הפרויקט. לציין מה הושלם ומה חסום. אין צורך להכין מצגת שלא נדרשה.

## נאמנות להגשה

דוגמה סינתטית אינה מחקר. רשימת plugins אינה חיבור. תפקיד writer אינו Skill מותקן. תמלול אינו הוכחת צפייה בווידאו. פוסט טבעי אינו הוכחה שהקול האישי נלמד. קוד קיים אינו הוכחה שנבדק. דוח נקי ללא ריצות בפועל אינו בדיקה.

## מדדי ערך

אפשר למדוד זמן הכנת פוסט ידנית מול התהליך החדש על אותו סוג תוכן, דירוג של עמית, מספר תיקונים וכמות הצעות שנבחרו מתוך כלל ההצעות. מדוד בפועל; אין להציב תוצאה מומצאת כדי לשכנע שהפרויקט הצליח.
