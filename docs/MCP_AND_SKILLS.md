# MCP וסקילים — מה להקים ומה להוכיח

> עדכון יישום 4.11.2026: קיימת כעת גרסת עבודה מקומית ופיילוט אמיתי עם פוסט, ביקורת, תיקון ותמונה. הפעלה: `python start.py`. ראו [מדריך העבודה](../docs/WORKBENCH_QUICKSTART.md), [מצב היישום](../docs/IMPLEMENTATION_PROGRESS.md) ו־[הפיילוט](../pilot/01-clear-request/README.md). התיאורים בהמשך של יכולות עתידיות/תשתית הם תוכנית הבסיס; המצב המעודכן והמגבלות מפורטים במסמכי העדכון.

## דרישת התרגיל

בתמונה נדרש להתחבר ל־MCP חיצוני ולהפעיל Skill מתאים כחלק מהעבודה. הגדרת שרת בקובץ, רשימת תפקידים או פרומפט אינם הוכחה שהדרישה בוצעה. נדרשות קריאת כלי מוצלחת ותוצאת עבודה שנשענת עליה, וכן הפעלת סקיל אמיתי ותיעוד השפעתו.

## חיבור חיצוני ראשוני

OpenAI מפעילה שרת MCP ציבורי לתיעוד, בכתובת `https://developers.openai.com/mcp`. לפי התיעוד הרשמי הוא read-only לתיעוד ואינו מבצע קריאות OpenAI API בשם המשתמש. הוא מתאים לבדיקת שימוש נכון ב־Codex ולמחקר פריט תוכן על יכולות OpenAI. הוא אינו מנוע חיפוש לכל הרשת ואינו יוצר מודל חינמי.

פקודות מתועדות — להריץ רק אם Codex CLI קיים ולבדוק את תחביר הגרסה:

```bash
codex --version
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
codex mcp list
```

אם קיים חיבור כזה, משתמשים בו ולא מוסיפים כפילות. שינוי תצורת משתמש גלובלית אינו נדרש כאשר חיבור זמין ברמת הפרויקט. החבילה כוללת `.codex/config.example.toml`, לא תצורה פעילה שדורסת הגדרות.

בדיקת קבלה: חיפוש תיעוד על יכולת Codex רלוונטית → קריאת עמוד → רישום שם כלי בפועל, זמן, פרמטרים לא רגישים, קישורים ותוצאה → שימוש בראיה בפוסט/בהחלטת בנייה. הרשימה `mcp list` לבדה אינה מספיקה. אם החיבור חסום, סמן blocked; אל תכריז שהתרגיל הושלם. יש לאמת מול המנחה אם חיבור תיעוד כחלק מהבנייה מספיק; הדגמה גם במחקר פוסט על Codex מצמצמת את העמימות.

## MCP מקומי למוצר — שלב נפרד

להקים server ב־stdio בעל כלים מינימליים: `list_sources`, `fetch_source`, `read_evidence`, `list_candidates`, `save_draft`. השמות הם חוזה יעד ולא כלים קיימים. השרת מפעיל את שירותי האפליקציה ולא מחזיק API בתשלום. אין כלי publish, arbitrary shell או קריאת קובץ מחוץ לנתוני הפרויקט.

נדרש smoke test אמיתי דרך לקוח MCP: handshake, tools/list וקריאת כלי עם תוצאה ומקרה שגיאה. בדיקת פונקציה Python לבדה אינה בדיקת MCP. שרת מקומי אינו תחליף אוטומטי לדרישה ״MCP חיצוני״ בתרגיל.

## סקילים

`skill-specs/*.md` מכילים מפרטים לבנייה; הם אינם מותקנים כרגע. Codex צריך לייצר סקילים repo-local לפי התיעוד הרשמי בגרסת הלקוח ולבדוק discovery והפעלה. אל תשנה סקילים גלובליים קיימים.

מפרטים: research-source, draft-community-post, daily-editorial, produce-explainer, quality-review. לכל סקיל: תנאי הפעלה, קלט, צעדים, פלט, טיפול בכשל וכללי עלות/אמינות. סקיל אמיתי יכלול `SKILL.md` עם metadata מתאים; אין להסתפק בהעתקת שם קובץ.

הוכחת קבלה: בחר סקיל כתיבה, הפעל אותו מפורשות על evidence pack, שמור את המזהה/נתיב והגרסה, טיוטת הפלט ולוג או אישור מהסשן שהסקיל נטען. בתוכנת runtime המקומית ניתן להשתמש באותה לוגיקת workflow, אבל אין לכנות שימוש בפרומפט בלבד ״Codex Skill מותקן״.

## ניהול יכולות ועלויות

אין להתקין plugins אקראיים, להריץ קוד של מקור חיצוני או לאשר שירות בתשלום כדי להשלים את התרגיל. כל plugin נבחן לפי מקור, רישיון, הרשאות ונתיב חיוב. סקילים ותצורות ישמרו במאגר הפרויקט; sync ל־remote רק אחרי שנקבע יעד מורשה.
